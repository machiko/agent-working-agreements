# 規則檔瘦身：每一行都要有存在的理由

> 適用於 CLAUDE.md、AGENTS.md、`.claude/rules/`、記憶索引。這些檔案每個 session 都會載入，越長，重要的規則越容易被淹沒。

## 留下一行規則的條件

逐行問自己：「拿掉這一行，agent 會不會做錯？」不會，就刪掉。

- 不寫 agent 本來就會做的事（「寫乾淨的程式碼」「注意安全」）。
- 不重述語言或框架的慣例，那些它已經知道了。
- 每條規則要附上理由或事故。沒有理由，遇到邊界情況就無法判斷要不要套用。
- 「IMPORTANT」「一定要」只留給真正零例外的一兩條。到處都加，就等於沒加。

## 不要重複，不要常駐不需要的東西

**為什麼：** 一次盤點發現，規則目錄裡同時有英文原版和一份舊的簡中翻譯。兩份內容已經分歧，簡中用語又和使用者要求的繁中相反，每個 session 白白多載入約 5,500 tokens。同一個目錄裡還有一份安裝說明 README，對 agent 完全沒用，也每次都被載入。

**怎麼做：**

- 同一套規則只留一種語言、一個版本。
- 規則目錄底下的 `.md` 都會被載入，所以說明文件、範本、草稿要放在目錄外面。
- 只跟特定檔案有關的規則，用 `paths` frontmatter 限定載入範圍（例如只在碰到 `**/*.php` 時才載入 Laravel 規則）。
- 有步驟的流程（部署、發版）寫成 skill，需要時才載入，不要放在常駐規則裡。
- 定期量測常駐內容的大小，並設定上限。

## 一再被違反的規則，就升級成 hook

同一條規則被違反兩次以上，代表寫在文字裡不夠用。可以用指令檢查的事（commit 格式、禁用指令、測試必跑），就改成 hook 強制執行，然後把原本那段文字精簡掉。

## 記憶索引也要瘦身

記憶索引每一行只寫標題和一句提示，細節放在各自的檔案裡。索引的一行一旦長成一段話，它就從索引變成了全文。
