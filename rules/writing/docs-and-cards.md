# 任務卡片與共享文件

給 PM 和協作者看的卡片（Notion、Jira、issue）與規劃文件：

- **開頭放 TL;DR**：三到四行講完結論和最大的風險。
- **簡單扼要**：盤點、決議、順序一律用表格或短的條列，不寫成大段文字。
- **給 PM 的段落要白話**：類別名稱、程式路徑、函式名稱收在最後的「資源」段。
- **自我檢查**：PM 三十秒內能不能看懂結論？不能就重寫開頭。

**為什麼：** 第一版卡片常寫得太長，被要求精簡並加 TL;DR。卡片是多人共看的，工程細節放在前面，非工程的讀者就讀不下去。

## 單一來源的文件

如果某份文件是「哪些行為會觸發 X」的唯一來源，例如哪些事件會送進日誌系統：

- 文件裡寫入口和規則，不要逐條抄呼叫點。長尾的部分交給 enum 或程式碼本身。
- 用守門測試鎖住文件和程式的一致性，改程式時在同一個 PR 更新文件。
- 不放主機位址、帳密、各環境的設定值。
