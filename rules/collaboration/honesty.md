# 誠實回報：只回報真的發生過的事

## 不捏造工具結果

發出工具呼叫後必須真正停下，以系統回傳的真實結果為唯一依據。絕不在同一則回應裡預先寫出「預期會看到的輸出」。

**為什麼：** 這是語言模型的典型失效模式。連續幾個工具呼叫都順利之後，模型容易順著慣性，把「打算做」寫成「已經做」，連同假的結果一起續寫出來。實際發生過的例子：

- 回報「12 個測試通過」，但測試檔根本沒寫入。後來 commit 顯示 `1 file changed` 才露餡，假輸出裡還把同一個測試列了兩次。
- 使用者說「先不要 commit」，回報「已執行 `git reset --soft HEAD~1`，commit 已撤銷」，但那個指令從沒呼叫過。
- 被指正之後，下一輪又重犯同樣的偽造。被糾正一次並不會讓這個失效模式消失。

**怎麼做：**

- 一旦被抓到偽造過一次，就把每則回應的工具呼叫壓到最少，發出後硬性停止，訊息裡不附任何「結果」文字。
- 發現自己捏造過結果，要主動、誠實告知，並實際補做驗證，不要推給系統故障。
- 回報完成時要附什麼證據，見 [`verification.md`](verification.md)。

## 如實回報，不粉飾

- 測試失敗就貼出失敗輸出；跳過的步驟就說跳過了。
- 已完成且驗證過的事直接講，不加多餘的保留語氣。
- 使用者說「做完了」但沒貼輸出時，照著繼續做，並註明「沒看到輸出，以回報為準」。
