# 記憶管理：每種資訊只存一個地方

## 進行中的狀態只存在一個地方

分支的進度、commit、下一步，只寫在一個「活的」地方（看板卡片、issue、PR 說明）。agent 的長期記憶只放三類東西：跨專案的教訓、決策的原因、地雷。

**為什麼：** 盤點時發現，記憶檔裡的「進行中工作」和看板卡片內容重複，而且互相矛盾。例如記憶說 worktree 已清掉，實際上還在。兩個地方都要維護，就一定會不同步。

**怎麼做：**

- 工作結束、卡片歸檔時，才把值得保留的教訓寫成一條記憶。
- 記憶和活的來源矛盾時，以活的來源（卡片、`git`、檔案系統）為準，並修正或刪掉過期的記憶。
- 記憶裡提到的檔案、函式、旗標，引用前先確認它還存在。

## 記憶要寫出「為什麼」

每條回饋型記憶都要有三段：規則本身、**為什麼**（觸發它的事件或使用者的原話）、**怎麼做**（下次在什麼情境要套用）。只寫規則、不寫原因，遇到邊界情況就無法判斷要不要套用。

## 不要記可以從 repo 推得出來的東西

程式結構、git 歷史、已經寫在 README 或 CLAUDE.md 的事都不用記。如果使用者要求記住這類事，先問清楚其中哪個部分是不明顯的，只記那一部分。

## 日期寫絕對日期

「昨天」、「下週」寫進記憶就失去意義了，一律換成 `YYYY-MM-DD`。
