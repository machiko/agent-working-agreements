# 資料範圍：列表、報表、匯出都要套用授權範圍

## 規則

有角色資料範圍（全域、區域、組織、團隊、個人）的系統，**所有列表、報表、資料匯出都必須套用目前使用者的範圍過濾**。只要有一個出口漏掉，低權限角色就能看到其他範圍的資料。

**為什麼：** 報表和匯出是最常被遺漏的出口。它們常走 raw SQL 或背景佇列，繞過了列表頁上已經套用的 model scope。

## 怎麼做

- 範圍邏輯集中在一個 service，提供一個「可序列化的過濾條件」入口。
- **佇列型報表**：在 controller dispatch 之前取得過濾條件，序列化放進 job，job 裡再傳給 service 和匯出類別。不要在 worker 裡重新解析「目前使用者」，因為 worker 裡沒有登入狀態。
- **raw SQL 報表**：從過濾條件取出對應的欄位，加到 WHERE 條件。
- **匯出類別只接收已經過濾好的資料**，不要讓它自己理解範圍規則。
- 列表授權和詳細頁授權是兩回事：能在列表看到一筆資料，不代表能打開它的詳細頁。兩者要分開判斷。
- 新增報表時，第一個要確認的就是「有沒有套用範圍」。

## 相關地雷

- 改了 worker 端的程式碼後，要重新啟動 worker 容器或程序。只發出 `queue:restart` 這類訊號，不一定會重新載入程式碼。
- 跨環境的資料（角色、權限）用穩定的 `code` 查詢，不要寫死自動產生的 ID。各環境的 ID 不一樣，見 [`../laravel/pitfalls.md`](../laravel/pitfalls.md)。
