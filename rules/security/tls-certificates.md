# TLS 憑證更換

## 瀏覽器開得了，不代表憑證鏈是對的

換證後要逐張核對伺服器送出的憑證鏈，並用行動裝置實測。

**為什麼：** 桌面瀏覽器會自己補齊缺的中繼憑證，也信任比較多的根憑證；行動裝置的信任清單比較少，不會幫你補。曾經有一份憑證包順序顛倒、還多塞了兩張舊根，瀏覽器完全正常，行動 App 卻全部連不上，被誤判成「App 綁了舊憑證、要等 App 更新」，問題拖了好幾個月。換成 CA 官方提供的完整鏈之後，舊版 App 不用更新就恢復了。

**怎麼做：**

- 用 CA 給的 fullchain 檔，不要自己拼接。
- 換完跑 `openssl s_client -connect <網域>:443 -servername <網域> -showcerts`，逐張確認：葉憑證在第一張，每一張的 issuer 等於下一張的 subject。
- 如果根憑證有交互簽署（cross-sign）版本，確認鏈裡有帶，舊裝置要靠它驗證。
- 驗收要用實機（至少一台 iOS），不能只用瀏覽器。

## 前面有 WAF／LB 時，換主機上的證不等於換了對外的證

TLS 如果在 WAF、負載平衡器或 CDN 終止，使用者看到的是那一層的憑證，主機上的憑證只用在內部那一段。

**為什麼：** 曾經兩台主機對外出示同一張新憑證，其中一台主機上的檔案其實還沒換，代表那台的 TLS 根本不在主機上終止。不知道有這一層，就會在錯的地方換證，或把連線問題錯怪到憑證。

**怎麼做：** 換證前先確認 TLS 在哪一層終止（比對對外出示的憑證指紋和主機上的檔案；WAF 常會多加一個自己的 session cookie）。查連線問題時，先比對對外的憑證、TLS 版本與路由是否一致，再懷疑憑證。

## 憑證與私鑰不烤進映像

憑證在執行時用唯讀方式掛載（例如 compose 的 `./ssl:/etc/ssl/private:ro`），不要在 build 時 `COPY` 進映像。

**為什麼：** 烤進映像的私鑰會留在 registry 每一個歷史版本裡，換證也帶不走，只能輪換私鑰再清 registry。

**怎麼做：** 換證流程寫成腳本：驗證新檔（私鑰與憑證相符、效期、鏈順序）→ 備份舊檔 → 替換 → 重建 web 容器 → 失敗自動還原。主機上要先放好憑證檔再部署，否則掛載到空目錄，web 服務會起不來。
