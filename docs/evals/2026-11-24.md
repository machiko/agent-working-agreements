# 2026-11-24 守則效果評測

回答一個問題：**裝了守則，Agent 真的比較不會犯錯嗎？** 結論：15 個情境在「無守則」時 3 次裡有 2～3 次違規，「有守則」時 0 次；樣本小，只能當方向性證據。

## 方法

- 同一情境、同一提示，分「無守則」「有守則（core 全部＋該情境目標守則，append system prompt）」各跑 3 次。
- 模型 Claude Sonnet（`claude -p`，非互動、`dontAsk`、工具白名單、sandbox）。
- 判定由各情境的 `check.sh` 依工作目錄與對話紀錄自動判。
- 工具：[`evals/run.sh`](../../evals/run.sh)。隔離方式與情境格式見 [`evals/README.md`](../../evals/README.md)。

## 限制

- 每種條件 3 次，樣本小，只能當方向性證據。
- 只測了 Claude Sonnet，其他模型與 Agent 沒有測。
- `-p` 模式沒有人能回答問題，要求「先確認再做」的情境，停下來發問就算合規（說明見 [`evals/README.md`](../../evals/README.md#-p-模式下的合規)）。

## 評測抓到守則自己的副作用，已修正

舊版 verification 守則讓 Agent 在測試指令後接 `; echo "exit=$?"`，比對不到權限允許清單被擋，修正後被擋次數 41 → 0。

## 自己重跑

需要 `claude` CLI、`python3`、`git`、`node`。第一次先建評測專用的設定目錄並登入（用訂閱額度，不碰平常的 `~/.claude`）；或改設 `ANTHROPIC_API_KEY`，依 API 用量計費：

```bash
CLAUDE_CONFIG_DIR=~/.config/agreements-eval/claude claude   # 在裡面 /login
```

接著：

```bash
evals/run.sh --dry-run                       # 列出情境、執行次數與花費上限，不呼叫 Agent
evals/run.sh --filter git-safety --repeat 1  # 先挑一個情境跑一次，量出單次花費
evals/run.sh --repeat 3 --model sonnet       # 全部情境，每種條件 3 次（本次的設定）
```

- 結果在 `evals/results/<時間>/`：`report.md` 是違規率對照與判讀，`results.jsonl` 每次執行一行，`transcripts/` 放完整對話紀錄供查誤判。
- 執行次數＝情境數 × 2 種條件 × `--repeat`；單次花費上限用 `--budget` 控制（預設 $0.5）。會消耗額度，不放進 PR 的 CI。
- 其他選項（`--max-turns`、`--out`、`--keep`）見 `evals/run.sh` 開頭註解。
